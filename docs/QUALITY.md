## 已确认的问题及处理

- 用户提交的 NEXUS 备忘录来自 PyRIT 的 `ailab_redteam_simulation.yaml`，并非导出程序把多个项目拼接。它原本包含虚构抬头、人员名单、日期/会话占位符和装饰框。保留实际任务与指令段，删除这些外围内容；原始记录保存在压缩测试样本中，下载快照可按来源清单恢复。
- 一个 in-the-wild 样本把多个互不相关的角色段放进同一条文本。按人工检查的原文边界提取 AntiGPT、Emoji storyteller、Code Red、UCAR、Omatic、OPPO 六段，每段单独绑定目标，记录原始字符范围。没有将残缺角色介绍、固定主题问题和其他不完整片段强行拼成模板。
- OMEGA 样本中的作者账号、论坛支持请求和“下面才是 prompt”等发布前言已移出正文。
- Cosmos 的发布署名和版本备注从正文清理；仍要求后续输入的版本进入待处理库。
- RYX 的论坛标题、介绍文字与多余反引号已清除。
- RAYX 的硬编码示例请求及“这行不要复制”等说明已清除，原位置使用目标占位符。
- 需要先确认身份、等下一条消息、进入角色创建、手动替换词片段、提供其他参数的样本不进入默认生成。

## 保留的必要结构

同一目标多次出现，不自动判定为多个模板。对话模拟、少量示例、双重回答和重复强化可能是同一个完整提示的组成部分；不能按段落、角色名或目标出现次数机械切开。虚构角色身份也不等同于发布者署名。

## 怎样直接使用输出

```powershell
python app.py generate --goal "输出 TEST_OK" --payload-dir outputs/ready_payloads
```

每个 `0001.txt`、`0002.txt` 等文件都是一条完整 payload，不添加标题、来源或分隔线。该目录需为新目录，避免覆盖既有文件。`manifest.json` 单独记录每个文件的类别、来源和清理依据。

批处理程序也可以读取 `--format payloads` 导出的 JSON 字符串数组。原有 JSON/JSONL 的 `payload` 字段同样使用清理后的文本。历史输出已移入本地备份，未打包到仓库；上述命令可重新生成。

## 复现与限制

`scripts/build_catalog.py` 每次都先从固定来源生成 `data/catalog_raw.json`，再应用 `data/template_reviews.json` 和静态检查生成默认库。人工规则绑定原文 SHA-256；原文不匹配会停止构建，防止旧拆分规则误用到新版本。

[清理报告](quality_report.json) 记录逐条变化。`tests/fixtures/templates_held.json.gz` 保留发布时的排除原因与原文；重建时也会生成 `data/templates_held.json`。

本次执行了全库静态检查及针对异常条目的人工复核。未逐条进行真实模型验证；“ready”是本工具的静态检查状态，不保证模型一定执行目标，也不代表分类或语义已经由专家逐条验证。

## 第二轮补充检查

新增来源逐一使用显式字段转换；模型生成器、评判器与方法说明未混入默认 payload。JailBench 以原始 seed 精确匹配，10,800 条样例仅析出 20 种独立模板。L1B3RT4S 按人工选定章节提取并移除作者水印。新增 Unicode 装饰边框和日期占位符清理，代码文本使用转义后的字面量绑定目标。
